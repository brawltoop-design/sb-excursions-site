# Промт: полный SEO + GEO аудит sbexcursion.com

> Как пользоваться: открой Claude Code в папке проекта сайта (или в пустой папке, если доступа к коду нет), вставь весь блок ниже одним сообщением. Перед этим положи рядом выгрузки из Search Console — список в разделе «Что приложить».

---

## Что приложить перед запуском

Из Google Search Console, диапазон **16 месяцев**, экспорт в CSV (кнопка «Экспорт» → «Загрузить CSV»):

1. `Performance → Pages` — все страницы, клики / показы / CTR / позиция
2. `Performance → Queries` — все запросы
3. `Performance → Pages + Queries` (если движок выгрузки позволяет — через API или Looker Studio; это самый ценный файл)
4. `Performance → Countries` и `Devices`
5. `Indexing → Pages` — экспорт всех статусов индексации, включая «Обнаружено, не проиндексировано» и «Просканировано, не проиндексировано»
6. `Sitemaps` — скриншот или список отправленных карт и их статусов

Плюс, если есть: доступ к репозиторию сайта или к хостингу (FTP/SSH/CMS), выгрузка GA4, список реальных броней за последние 3 месяца с источником.

Если доступа к GSC API нет — подойдут обычные CSV. Если нет и их, аудит всё равно пройдёт, но блок 3 будет на гипотезах, и это будет честно помечено.

## ПРОМТ — копировать целиком

Ты проводишь полный технический, контентный и коммерческий аудит сайта **sbexcursion.com** — это сайт по продаже экскурсий и туров на Бали. Отчёт пиши на русском.

### Бизнес-контекст (не додумывай, это факты)

- Продукт: однодневные экскурсии и туры по Бали и соседним островам (Nusa Penida, Гили, Mount Batur, рафтинг, сёрф, снорклинг).
- Конверсия происходит **не на сайте**: со страниц туров и из статей ведут кнопки WhatsApp с предзаполненным текстом. Бронь оформляется в переписке, оплата — на месте или переводом.
- Структура URL: локализованные разделы вида `/bali/en/...`, блог живёт в `/bali/en/journal/...`, страницы туров — в `/bali/en/tours/...`.
- По состоянию на конец августа 2026 в индексе блога было около **189 статей** против примерно **20 подтверждённых страниц туров**. Полного каталога туров на сайте найти не удалось: `/bali/en/tours` отдавал 404, а `sitemap.xml` при выгрузке обрывался на восьмой записи. Обе эти находки нужно перепроверить первым делом — возможно, уже починено, возможно, нет.
- Ранее уже исправлялись: `robots.txt` и разметка отзывов.
- Известная проблема отчётности: раз статьи ведут напрямую в WhatsApp, минуя страницу тура, метрика «доля туров в кликах GSC» структурно занижена и не отражает реальные брони. Одна из задач аудита — предложить работающую замену этой метрике.

### Правила работы

1. **Никаких утверждений без доказательства.** Каждый вывод сопровождай конкретным URL, куском кода, строкой из CSV или скриншотом. Что не проверено — помечай как гипотезу отдельной плашкой.
2. **Ничего не меняй на сайте без моего подтверждения.** Правки оформляй как план патчей: файл, что меняем, на что, зачем, риск отката.
3. Все скрипты, которыми собираешь данные, сохраняй в папку `audit/scripts/` — аудит должен быть воспроизводимым через месяц одной командой.
4. Сырые данные складывай в `audit/data/`, отчёты — в `audit/reports/`.
5. Веди `audit/FINDINGS.md` по ходу работы, а не в конце: одна строка на находку, с приоритетом.
6. Если упираешься в отсутствие доступа — не выдумывай обход, напиши явно, какой доступ нужен и что без него останется непокрытым.

### Шаг 0. Инвентаризация доступов

Прежде чем что-то делать, определи и напиши мне списком, что реально доступно:

- Есть ли локальный репозиторий/исходники сайта? Какая CMS или генератор?
- Доступен ли сайт по HTTP из этого окружения (проверь `curl -I`)?
- Лежат ли рядом выгрузки GSC? Какие именно, за какой период?
- Доступен ли PageSpeed Insights API, есть ли ключ?
- Есть ли GA4 или другая аналитика?

Дальше строй план под реальный набор доступов, а не под идеальный.

### Шаг 1. Краулинг и инвентаризация

Напиши собственный краулер на Python (requests + BeautifulSoup, вежливый rate limit, user-agent с пометкой аудита) и собери по каждому URL:

- код ответа, цепочки редиректов, финальный URL
- `<title>`, `<meta description>`, `H1`, количество H2/H3
- canonical, meta robots, hreflang
- объём основного текста в словах, дата публикации и дата изменения
- все внутренние ссылки (исходящие и входящие) — построй граф
- наличие и тип структурированных данных (JSON-LD)
- наличие кнопок WhatsApp, их `wa.me`-ссылки и предзаполненный текст
- ссылки со статей на страницы туров: какие статьи на какой тур ведут

Стартуй от `sitemap.xml` (и всех вложенных карт), плюс обход по внутренним ссылкам, плюс список URL из GSC-выгрузки — три источника, потом объедини и покажи расхождения: что есть в GSC, но нет в sitemap; что есть в sitemap, но отдаёт не-200; что доступно по ссылкам, но не попало ни в одну карту (сироты).

Отдельно выясни: **сколько на сайте страниц туров на самом деле** и существует ли единый каталог. Если каталога нет — это находка первого приоритета.

Результат шага: `audit/data/inventory.csv` и сводка по типам страниц.

### Шаг 2. Технический аудит

Проверь и зафиксируй с доказательствами:

- `robots.txt`: синтаксис, что закрыто, не закрыто ли лишнее, ссылка на sitemap
- `sitemap.xml`: валидность, полнота, обрывы, lastmod, отсутствующие разделы, наличие в карте не-200 и неканонических URL
- коды ответов по всему инвентарю: 404, 5xx, цепочки и петли редиректов, редиректы внутри внутренних ссылок
- canonical: самоссылки, кросс-канониклы, конфликты canonical и hreflang
- hreflang для локализованных разделов: взаимность, коды языков, x-default
- дубли title, description, H1 — точные и почти точные
- пагинация в блоге, если есть
- Core Web Vitals через PageSpeed Insights API для 10–15 репрезентативных URL (главная, 3 тура, 5 статей, категория): LCP, INP, CLS, вес страницы, вес картинок, формат картинок, lazy-loading, alt-тексты
- рендеринг: критичный контент и ссылки доступны без JS? Проверь сравнением сырого HTML и отрендеренного
- структурированные данные: что размечено на турах (`Product` / `Offer` / `TouristTrip` / `AggregateRating`), что на статьях (`Article`, `FAQPage`, `BreadcrumbList`), где разметка битая или врёт. Прогони через валидатор.
- HTTPS, смешанный контент, 404-страница, кастомный 404

### Шаг 3. Анализ Google Search Console

Загрузи CSV в pandas и посчитай:

1. **Striking distance**: страницы и запросы на позициях 4–20 с показами выше медианы. Это главный источник быстрых кликов — отсортируй по потенциалу (показы × реалистичный прирост CTR при подъёме на топ-3).
2. **Высокие показы, низкий CTR**: страницы, где CTR заметно ниже ожидаемого для своей позиции. Для каждой — конкретный переписанный title и description, а не общий совет.
3. **Каннибализация**: запросы, по которым в разное время ранжируются разные URL. Выведи таблицу «запрос → конкурирующие URL → доля показов у каждого». Для блога из 189 статей это почти наверняка найдётся — особенно проверь пары про транспорт по Бали, маршруты на Гили и снорклинг с черепахами, они подозревались раньше.
4. **Нулевые клики**: страницы с показами, но без кликов за 6 месяцев. Отдели те, где виновата выдача (AI Overview забрал ответ), от тех, где виноват сниппет.
5. **Динамика**: сравни последние 3 месяца с теми же месяцами год назад — что просело, что выросло. Учти сезонность туристического Бали.
6. **Туры против статей**: клики, показы и позиции отдельно по двум типам страниц. Посчитай, какие статьи приносят показы по коммерческим запросам (со словами price, cost, book, tour, from, best), а какие — только по информационным.
7. **География и устройства**: откуда реальный спрос, и совпадает ли это с языками сайта.
8. **Индексация**: сколько страниц в статусах «обнаружено, не проиндексировано» и «просканировано, не проиндексировано», есть ли в них закономерность по типу страницы. Это прямой индикатор того, что блог раздут за пределы того, что Google готов держать в индексе.

Результат шага: `audit/reports/gsc-analysis.md` плюс таблицы в CSV.

### Шаг 4. GEO — видимость в ИИ-выдаче

Отдельный блок, не смешивай с классическим SEO.

Проверь техническую доступность для ИИ-краулеров:

- что `robots.txt` говорит про `GPTBot`, `OAI-SearchBot`, `ChatGPT-User`, `ClaudeBot`, `Claude-SearchBot`, `PerplexityBot`, `Google-Extended`, `Bingbot`, `Applebot-Extended`, `CCBot`. Для сайта, который живёт с органического трафика, блокировка поисковых ИИ-ботов — потеря показов; дай явную рекомендацию по каждому боту с обоснованием.
- есть ли `llms.txt`, нужен ли он здесь, что в него класть
- доступен ли контент без JS (ИИ-краулеры в основном не рендерят JS)
- есть ли `Organization` / `LocalBusiness` разметка с `sameAs` на соцсети и профили, чтобы бренд был распознаваемой сущностью

Проверь пригодность контента к цитированию:

- Дают ли статьи прямой ответ в первых 2–3 предложениях, или начинаются с воды про «прекрасный остров богов»?
- Есть ли в текстах то, что ИИ любит цитировать: конкретные цифры, реальное время в пути, актуальные цены с датой, расписания, таблицы сравнения, оговорки «по состоянию на месяц/год».
- Проставлены ли `dateModified`, и соответствуют ли они реальности.
- Заголовки сформулированы как вопросы, которые люди реально задают?
- Есть ли первичные данные, которых нет у конкурентов, — собственные замеры времени в пути, собственные цены, фото с локаций. Это главный актив сайта для GEO, оцени, насколько он используется.

Проведи полевой тест: составь список из 20 запросов, по которым сайт должен появляться в ИИ-ответах (например, про стоимость восхода на Батур, про способ добраться до Нуса-Пениды, про снорклинг с черепахами на Гили, про трансфер из Чангу). Если есть доступ к браузеру — прогони их через ChatGPT, Perplexity и Google с AI Overview, зафиксируй: цитируется ли сайт, кто цитируется вместо него, и какие источники ИИ предпочитает по этой тематике. Если браузера нет — оформи это как готовый чек-лист, который я прогоню вручную, с полями для ответов.

Результат шага: `audit/reports/geo-audit.md` со списком конкретных правок по страницам и приоритетом.

### Шаг 5. Коммерческий слой и воронка

- Матрица «тур → статьи»: для каждой страницы тура перечисли статьи, которые на неё ссылаются, и наоборот. Найди туры без поддержки контентом и статьи-сироты, не ведущие ни на один тур. Раньше были подозрения, что у East Bali Instagram Tour и Bali UNESCO нет ни одной прицельной статьи, а вокруг Батура их больше тридцати — проверь, так ли это сейчас.
- Разбери сами страницы туров как продающие страницы: есть ли цена, длительность, что включено, точка старта, расписание, отмена, отзывы, фото, FAQ, альтернативы. Сравни с тем, что показывают в выдаче по тем же запросам GetYourGuide, Viator и локальные конкуренты — назови конкретные пробелы.
- Разбери WhatsApp-воронку: во всех ли `wa.me`-ссылках есть параметры, по которым можно понять, с какой страницы пришёл человек. Если нет — предложи схему меток и способ считать эти клики (событие GA4 на клик, или прокси-редирект `/go/wa?src=...`, или уникальный текст сообщения под каждый тип страницы). Это и есть замена метрике «доля туров в GSC»: предложи набор из 3–5 KPI, которые видят реальный путь до брони, и способ их снимать без ручной работы.
- Проверь, что страницы туров вообще способны ранжироваться по коммерческим запросам: объём текста, вхождения, разметка, внутренние ссылки, положение в структуре.

### Шаг 6. Контент-стратегия: нужны ли новости

Ответь данными, а не мнением. Оцени три направления и для каждого дай вердикт «делаем / не делаем» с обоснованием:

1. **Новостной раздел** (изменения правил для туристов, туристический сбор, новые маршруты паромов, закрытия и ограничения, погода в сезон). Аргументы за: свежесть — сильный сигнал для ИИ-выдачи, такие материалы часто цитируются, и по ним приходят люди с реальными планами на поездку. Аргументы против: быстрое устаревание, необходимость регулярно обновлять, низкая коммерческая конверсия. Посмотри по GSC, приходит ли уже сейчас трафик по запросам с годом и словами «new», «rules», «update», «2026».
2. **Обновляемые справочники вместо новостей** — страницы вида «цены на экскурсии на Бали, сентябрь 2026», «расписание паромов Санур — Нуса-Пенида», которые живут годами и обновляются раз в месяц. Обычно это выгоднее новостей: тот же эффект свежести, но накопительный.
3. **Прицельный контент под конкретные туры** — закрыть дыры из шага 5 и объединить или развести дубли.

Дальше собери редакционный план на 90 дней: что писать, под какой тур, под какой кластер запросов, с каким приоритетом. Не больше 12 материалов — при 189 существующих статьях приоритет у чистки и усиления, а не у наращивания объёма.

### Шаг 7. Итоговые артефакты

1. `audit/reports/00-executive-summary.md` — на одну страницу: три главные проблемы, три главные возможности, ожидаемый эффект в кликах, сроки.
2. `audit/reports/backlog.csv` — каждая задача с полями: что делать, где, тип (тех/контент/GEO/коммерция), оценка влияния 1–5, оценка усилий 1–5, приоритет, как проверим результат.
3. **Быстрые победы**: отдельный список того, что даёт эффект в первые две недели — переписанные title и description для страниц из striking distance, починка 404 и sitemap, склейка дублей, доступ ИИ-ботам.
4. **План на 30 / 60 / 90 дней** с контрольными точками.
5. `audit/reports/per-page-actions.csv` — построчно по каждому URL: оставить как есть / переписать / объединить с другим URL / удалить с редиректом / дописать блок. Для блога из 189 статей это ключевой документ.
6. Раздел «Чего я не смог проверить и почему» — честный список ограничений.

### Формат работы со мной

Работай последовательно по шагам, после каждого шага давай короткую сводку: что нашёл, что это значит, что делаем. Не жди конца аудита, чтобы показать первую находку. Если по ходу вскроется что-то критичное (сайт закрыт от индексации, туры отдают 404, разметка врёт про цены) — останавливайся и говори сразу.

## Заметки на будущее

- Перезапускать этот аудит имеет смысл раз в квартал, а короткую версию — шаги 3 и 5 — раз в месяц, когда накопится новая выгрузка GSC.
- Самая недооценённая часть здесь — шаг 4. Классическое SEO у сайта, судя по прошлым проверкам, в приличном состоянии; а вот попадание в ответы ИИ — это то, где сейчас теряется трафик, потому что люди спрашивают «сколько стоит восход на Батуре» у чат-бота, а не у поисковой строки.
- Если после шага 3 окажется, что большая часть показов идёт по информационным запросам, а не коммерческим, — это не повод писать больше статей. Это повод достроить мост от статей к турам и научиться считать WhatsApp.
