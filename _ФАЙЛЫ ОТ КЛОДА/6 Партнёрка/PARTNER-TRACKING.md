# Отслеживание партнёров: QR → сайт → WhatsApp → бронь

Для страницы `/work-with-us`. Дата: 9 августа 2026.

---

## Проблема, как она есть сейчас

На странице написано: **«No links, no dashboards. Your name is the tracking.»**

Для партнёра это отличное обещание — ему не надо возиться с кабинетами. Но как система
учёта оно течёт в одном месте: **всё держится на том, что гость вспомнит назвать имя
виллы.** Половина не вспомнит. Гость приходит в WhatsApp, пишет «hi, price for Nusa
Penida?» — и ты не знаешь, откуда он. Партнёр не получит свои $10 и решит, что ты жулик.

Хорошая новость: чинится это так, что обещание на странице остаётся правдой. Партнёр
по-прежнему ничего не делает — ему просто выдаётся готовый QR, а трекинг работает сам.

---

## Как это устроено — четыре слоя

```
[1] QR на визитке виллы
     ↓  ссылка с кодом партнёра
[2] Твой сайт — код запоминается на 30 дней
     ↓  гость жмёт «Book on WhatsApp»
[3] WhatsApp открывается, код УЖЕ ВНУТРИ сообщения
     ↓  ты видишь его в чате
[4] Таблица броней — записываешь код, платишь партнёру
```

**Слой 3 — это и есть ответ на твой вопрос «как отследить покупку без эквайринга».**
Покупка у тебя происходит не на сайте, а в переписке. Значит и метку надо тащить
в переписку, а не в платёжку. Эквайринг для этого не нужен вообще.

---

## Слой 1. Ссылки для QR

Каждому партнёру — свой короткий код латиницей, без пробелов:

```
https://www.sbexcursion.com/?ref=villa-mango
https://www.sbexcursion.com/?ref=surf-uluwatu
https://www.sbexcursion.com/bali/en/tours/nusa-penida-full-day-tour?ref=cafe-canggu
```

Код можно вешать на любую страницу — работает и с главной, и с конкретным туром.
Для кафе и вилл логичнее вести на конкретный тур, который они чаще советуют.

**Правила именования кода:** только латиница, цифры, дефис и подчёркивание. Никакой
кириллицы и пробелов — скрипт их вырежет. Делай понятным: `villa-mango`, а не `p1`,
чтобы ты сам через полгода понял, кто это.

QR генерируй с этой ссылкой любым генератором. Печатать код на визитке отдельно не
надо, он внутри QR.

## Слой 2 + 3. Скрипт на сайт

Вставить **на все страницы** перед закрывающим `</body>`. Один раз, дальше работает само.

```html
<script>
(function () {
  var TTL_DAYS   = 30;                 // сколько помним партнёра после перехода
  var STORAGE_KEY = 'sb_partner_ref';
  var LABEL      = 'Recommended by';   // как подпись выглядит в сообщении гостю

  function sanitizeRef(v) {
    if (!v) return null;
    var clean = String(v).trim().slice(0, 32).replace(/[^A-Za-z0-9_-]/g, '');
    return clean.length ? clean : null;
  }

  function readFromUrl() {
    try {
      var q = new URLSearchParams(window.location.search);
      return sanitizeRef(q.get('ref') || q.get('utm_campaign'));
    } catch (e) { return null; }
  }

  function save(ref) {
    try { localStorage.setItem(STORAGE_KEY, JSON.stringify({ ref: ref, t: Date.now() })); }
    catch (e) {}
  }

  function load() {
    try {
      var o = JSON.parse(localStorage.getItem(STORAGE_KEY) || 'null');
      if (!o || !o.ref) return null;
      if (Date.now() - o.t > TTL_DAYS * 86400000) return null;
      return sanitizeRef(o.ref);
    } catch (e) { return null; }
  }

  function buildWaHref(href, ref) {
    var u;
    try { u = new URL(href, window.location.href); } catch (e) { return href; }
    var host = u.hostname.replace(/^www\./, '');
    if (host !== 'wa.me' && host !== 'api.whatsapp.com') return href;
    var text = u.searchParams.get('text') || '';
    if (text.indexOf('(' + LABEL + ':') !== -1) return href;   // уже стоит
    var suffix = '(' + LABEL + ': ' + ref + ')';
    var newText = text ? text + '\n\n' + suffix : suffix;
    u.searchParams.delete('text');
    var rest = [];
    u.searchParams.forEach(function (v, k) {
      rest.push(encodeURIComponent(k) + '=' + encodeURIComponent(v));
    });
    // encodeURIComponent даёт %20, а не + — WhatsApp иначе покажет плюсы вместо пробелов
    rest.push('text=' + encodeURIComponent(newText));
    return u.origin + u.pathname + '?' + rest.join('&');
  }

  var ref = readFromUrl();
  if (ref) save(ref); else ref = load();
  if (!ref) return;

  function patchAll() {
    var links = document.querySelectorAll('a[href*="wa.me"], a[href*="api.whatsapp.com"]');
    for (var i = 0; i < links.length; i++) {
      links[i].href = buildWaHref(links[i].getAttribute('href'), ref);
    }
  }

  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', patchAll);
  } else {
    patchAll();
  }

  // страховка: ловим клик по ссылкам, добавленным на страницу позже
  document.addEventListener('click', function (e) {
    var a = e.target && e.target.closest ? e.target.closest('a') : null;
    if (!a || !a.href) return;
    if (a.href.indexOf('wa.me') === -1 && a.href.indexOf('api.whatsapp.com') === -1) return;
    a.href = buildWaHref(a.getAttribute('href'), ref);
  }, true);
})();
</script>
```

### Что увидит гость

```
Hi! I'd like to book a Bali tour.

(Recommended by: villa-mango)
```

Специально сделано **человекочитаемо и честно**, а не в виде `[ref:xk29]`. Причина
простая: гость видит текст перед отправкой и может его стереть. Строчку «кто
порекомендовал» стирают редко — она выглядит нормально и вежливо. А криптомусор
стирают охотно, потому что похоже на слежку.

### Что проверено

Логику прогнал тестами: подстановка кода, отсутствие дублей при повторном клике,
работа с `wa.me` и `api.whatsapp.com`, сохранность исходного текста и параметра
`phone=`, вырезание попыток инъекции через `?ref=`, кодировка пробелов через `%20`.
17 проверок, все прошли. Что **не** проверено — работа на живом сайте: вставь на одну
страницу, отсканируй свой же QR телефоном и посмотри, что приехало в WhatsApp.

## Слой 1 отдельно: считать переходы

Тут ничего делать не надо — **у тебя уже стоит Vercel Web Analytics**, и в нём есть
вкладка **UTM Parameters** рядом с Referrers. Она подхватит `utm_campaign`
автоматически.

Поэтому если хочешь видеть переходы в Vercel, используй в QR такой формат:

```
https://www.sbexcursion.com/?utm_source=partner&utm_medium=qr&utm_campaign=villa-mango
```

Скрипт выше читает и `ref=`, и `utm_campaign=` — так что работают оба варианта.
Короткий `?ref=` удобнее для печати, длинный с utm — лучше виден в аналитике.
Можно взять utm-формат и не думать.

⚠️ Помни, что мы выяснили про Vercel Analytics: он считает всё подряд, включая ботов
и твои собственные заходы. Для «сколько людей реально написали» это не источник
правды — источник правды это WhatsApp.

## Слой 4. Таблица броней

Автоматизировать нечем: оплата кэшем и переводом, никакой системы, которая бы сама
знала о факте покупки, у тебя нет. Значит источник правды — твоя таблица.

Минимальный набор колонок:

| Дата заявки | Код партнёра | Имя гостя | Тур | Кол-во чел | Дата тура | Статус | К выплате | Выплачено |
|---|---|---|---|---|---|---|---|---|
| 09.08 | villa-mango | Marc | Nusa Penida full day | 2 | 14.08 | подтверждён | $10 | — |

Статусы: `заявка` → `подтверждён` → `съездил` → `выплачено`. Платишь по обещанию
со страницы — сразу после дня тура.

## Открытая аналитика для партнёров — честный разбор

Ты спросил, можно ли сделать так, чтобы партнёры сами смотрели свои цифры. Тут надо
разделить две вещи, потому что они разной сложности.

**Переходы (клики) — показать легко.** У Plausible и Umami есть публичные дашборды
по ссылке без логина. У Umami бесплатный тариф навсегда: 100k событий в месяц, 3 сайта,
хранение 6 месяцев. У Plausible дешёвый тариф от $9/мес за 10k просмотров.

**Но есть засада:** публичный дашборд показывает данные **всего сайта целиком**.
Партнёр увидит и чужие цифры, и общую посещаемость. Для тебя это скорее нежелательно.

**Покупки — показать автоматически нельзя вообще.** Они живут в твоей таблице и в
твоей голове. Никакой аналитический сервис о них не узнает, потому что нет ни
эквайринга, ни системы бронирования. Чтобы партнёр видел свои брони в реальном
времени, нужно писать маленькое веб-приложение: база + страница на партнёра + защита
доступа. Это уже разработка, не настройка.

**Что я бы делал на твоей стадии.** У тебя партнёрка только запускается, партнёров
единицы. Собственный кабинет под трёх человек — это оверинжиниринг, который съест
неделю и не окупится. Гораздо сильнее работает простое:

> Раз в неделю пишешь партнёру в тот же WhatsApp:
> «За неделю от тебя двое: Marc (Nusa Penida, 14 авг) и Sofia (rafting, 16 авг).
> $15 отдам в пятницу.»

Это конкретнее любого дашборда, занимает две минуты, и главное — **держит живой
контакт**, а контакт с партнёром тебе важнее, чем красивый интерфейс. Дашборд имеет
смысл строить, когда партнёров станет 15–20 и рассылка вручную начнёт болеть.

Если всё-таки захочешь публичную страницу раньше — самый дешёвый честный вариант это
одна общая страница «сколько всего гостей привели партнёры в этом месяце» без разбивки
по людям. Её можно сделать статической и обновлять руками раз в неделю из той же
таблицы.

## Порядок действий

1. Придумать коды для тех партнёров, что уже есть (латиницей, понятные)
2. Вставить скрипт на сайт
3. Проверить на себе: отсканировать свой QR, дойти до WhatsApp, увидеть код в тексте
4. Сгенерировать QR каждому партнёру
5. Завести таблицу броней
6. Раз в неделю — сообщение партнёру с его цифрами

Дашборды — потом, когда партнёров станет много.
